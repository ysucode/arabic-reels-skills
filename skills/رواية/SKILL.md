# رواية

فيلم عمودي بلقطة واحدة من قصة حقيقية، من أول رابط إلى النشر. كل قرار يبقى عند المستخدم، والباقي علينا.

اكتب للمستخدم بالعربي البسيط. الوقفات الأربع تحت هي بواباته، وما تتجاوزها حتى لو كان الطريق واضح:

1. **القرارات** (الخطوة 2)
2. **النص والستوريبورد** (الخطوة 5)
3. **الصوت ثم الموسيقى** (الخطوتان 6 و7)
4. **المسودة ثم النشر** (الخطوتان 8 و9)

## 1. افهم المرجع

إذا فيه رابط، شغّل سكل `watch`، وبعدها حلل الإيقاع:

```bash
python -I ~/.claude/skills/onetake/scripts/analyze_ref.py <video.mp4> --out <dir>/ana
```

قل للمستخدم بصراحة وش شفت: الطول، والقطعات، ونسبة الثبات، وكم إطار عاينت فعلاً. المرجع للدراسة فقط، فلا تنسخ نصه ولا مشاهده ولا تصميم شخصياته.

## 2. القرارات: سؤال واحد كل مرة

استخدم أسلوب `grill-me`: سؤال واحد، معه توصيتك وسببها، ثم انتظر الجواب. أزر الرد يوضح خيارين كحد أقصى.

| # | السؤال | التوصية الافتراضية |
|---|---|---|
| 1 | موضوع القصة | نفس الحادثة بنص جديد إذا كانت حقيقية وقوية |
| 2 | المدة | 60 ثانية. أطول من كذا ينهك اللقطة الواحدة |
| 3 | الفكرة الرابطة | اعرض 3 أفكار تختلف في طريقة الانتقال |
| 4 | الشكل | نابع من القصة. لا تكرر شكل الفيلم السابق |
| 5 | الصوت | صوت المستخدم `nhJWWCFdNdusuVUT3x19` دايماً كخيار أول، وموسيقى Eleven Music، ومؤثرات Kenney |
| 6 | شخصية لها صوت؟ | صوت مميز للجمل المقتبسة فقط |
| 7 | المصادر على الشاشة | بدون. تصل لمن يكتب كلمة التعليق |
| 8 | كلمة التعليق | كلمة تستحق الرد، مثل «تقرير»، بسطر يظهر والكاميرا تتحرك |

لكل فكرة في السؤال 3 اذكر: أول إطار، وما الذي ينقل كل مشهد للتالي، وما تسمح به وما تمنعه. أفكار تنفع: كاميرا عبر الأحجام، أو عنصر واحد يتحول، أو تفاعل متسلسل. قواعد `virality` و`onetake` مرجع للفكرة والإيقاع.

إذا صار السؤال مو له داعي لأن جوابه واضح من كلام المستخدم، خذ الجواب وانتقل.

## 3. تحقق من القصة

ابحث عن المصدر الأصلي واقرأه، مو الأخبار عنه. ثبت كل رقم بجدول: الجملة، والدليل، والمصدر. الريلات كثيراً تبالغ، فإذا لقيت جملة مو دقيقة في المرجع قلها للمستخدم وصححها في نصك.

إذا كانت جملة في النص صياغة تمثيلية لسؤال أو رسالة، اكتبها كذا في الجدول وقلها للمستخدم. اذكر السياق اللي يحفظ العدل، مثل «لم تتأثر بيانات العملاء»، كتوضيح قصير على الشاشة.

## 4. جهز المشروع

```bash
python ~/.claude/skills/رواية/scripts/new_film.py <slug>
```

ينشئ `content-studio/<slug>/` فيه `proto/` و`voice/` و`music/` و`film/` و`vendor/`، ويركب three.js والأدوات. وأنشئ مجلد الفيديو في `2-المحتوى والعمل الحر/`، وفيه `نص_الفيديو.md` و`storyboard.md`.

المحرك في `references/engine.md`: اقرأه قبل تعديل `comp.src.html`. الملف الجاهز مثال كامل يعمل، فاستبدل مشاهده وألوانه ولا تكرره.

## 5. النص والستوريبورد: الموافقة الأولى

اكتب النص بجمل قصيرة، ولكل جملة وقت تقريبي وحدث على الشاشة. افحص الجملة الخاطفة بقائمة `virality`، واذكر أي مخالفة مقصودة.

ابني نموذجاً فعلياً، وأرسل إطارات حقيقية منه، لأن المستخدم يحكم أفضل على صورة منها على وصف:

```bash
cd content-studio/<slug>/proto
node build.js
node stills.js storyboard.png 0,3,6,12,20,30,40,50,60 6 300
```

اقرأ الصورة بنفسك وأصلح الواضح قبل ما ترسلها، ثم أرسلها بـ`SendUserFile`. وقل بصراحة وش ما زال غير مختبر، مثل الحركة المتصلة.

## 6. الصوت

- **التوليد:** `creative_generate_speech` بنموذج `eleven_v4`، ونسختين. **اقترح دايماً صوت المستخدم** `voice_id: nhJWWCFdNdusuVUT3x19` كخيار أول للراوي، ومرره كما هو بدل ما تختار صوتاً غيره. إذا قال المستخدم يبي غيره، استخدم `creative_list_voices`. اكتب الأرقام كلاماً. تكلفة الدقيقة قرابة 744 رصيد للنسخة.
- **الانتظار:** التوليد ياخذ قرابة دقيقة. استخدم أمر انتظار في الخلفية بدل تكرار الفحص.
- **القياس:** نزل النسخ في `voice/takes/`، ثم `python measure.py takes`. استخدم `python` العام، لأن `faster_whisper` مو في `.venv`.
- **الحدود:** Whisper يخطئ في اللهجة وحدود الكلمات، فلا تعتمد عليه وحده للقص. خذ نقاط القص من `silencedetect` في ffmpeg.
- **السمع:** أنت ما تسمع. قل هذا، وحدد للمستخدم وين يركز.

**صوت الشخصية:** ولّد الجملة بصوت من `creative_list_voices`، ثم:

```bash
python robot.py agent/source.mp3      # يطلع 3 درجات، وكل واحدة داخل كلام الراوي
python assemble.py                    # يبني voice.wav وtiming.json
```

قبلها عبّئ `voice/config.json`. الدرجة 2 غالباً الأنسب، لكن خله يسمع الثلاث.

## 7. الموسيقى

عبّئ `music/sections.json` من أوقات الصوت، ثم `python generate.py v1 v2`. ثم امزج كل نسخة تحت الصوت عشان يسمعها في سياقها، وأرسل له النسختين:

```bash
ffmpeg -y -i ../voice/voice.wav -i v1.mp3 -filter_complex "[0:a]aformat=sample_rates=44100:channel_layouts=stereo,asplit=2[vo][sc];[1:a]aformat=sample_rates=44100:channel_layouts=stereo,volume=-9dB[m];[m][sc]sidechaincompress=threshold=0.04:ratio=5:attack=15:release=260[md];[vo][md]amix=inputs=2:normalize=0:duration=longest,loudnorm=I=-16:TP=-3:LRA=11[out]" -map "[out]" -b:a 192k preview-v1.mp3
```

- مجموع الأقسام يساوي طول الفيلم، وأقل قسم 3000 ms.
- حقل `text` يبقى فاضي، لأن النص يتحول لكلمات مغناة.
- أي رفض `copyrighted_material_detected` غالباً سببه كلمة في الوصف، مثل `thriller`. احذفها بلا تقليد لأي عمل.
- قس منحنى الطاقة لكل نسخة وقارنه بالستوريبورد.

## 8. المسودة: الموافقة الثالثة

اضبط `CAPS` و`KEYS` على `voice/timing.json`، وعدّل الأحداث في `film/score.py`، ثم:

```bash
cd proto && node build.js && node render.js 60 ../film/frames60 4
cd ../film && python score.py v1        # v1 هو ملف الموسيقى المختار
ffmpeg -y -framerate 60 -i frames60/%05d.jpg -i mix.wav -c:v libx264 -preset slow -crf 20 -maxrate 25M -bufsize 50M -pix_fmt yuv420p -c:a aac -b:a 256k -movflags +faststart -shortest ../../export/<slug>-v1.mp4
```

الرندر الكامل ياخذ قرابة دقيقة، فصلح وأعد الرندر بدون تردد. افحص قبل ما ترسل:

- **قفزات:** `select='gt(scene,0.3)'`. أغلبها شيء عبر الكاميرا، مثل مجلد أو شخصية.
- **إطارات فاضية أو سودا:** لوحة `sheet.js` بقرابة 45 إطار، واقرأها بنفسك.
- **المواصفات:** ffprobe، والصوت قرب -16 LUFS وقمة أقل من -3 dBFS.
- **الإيقاع:** `verify_promo.py` من onetake. بند الهدوء غالباً يفشل مع موسيقى حاضرة، فبلغ بالنتيجة كما هي.

اذكر للمستخدم وش فحصت وكيف، ووش ما تقدر تحكم عليه. جهز بعد موافقته نسخة الرفع `-crf 23 -maxrate 14M`.

## 9. النشر: الموافقة الأخيرة

الموافقة على الفيديو مو موافقة على النشر، فانتظر طلباً صريحاً. اكتب الوصف والهاشتاقات، وقرر مع المستخدم وسم محتوى AI، ولا تفترض جوابه. نبهه إذا القرار يخص شروط منصة أو موسيقى، ونفذ اللي يختاره.

**الرابط العام:** `media_upload` من Higgsfield، ثم:

```bash
curl -X PUT -H "Content-Type: video/mp4" -H "If-None-Match: *" --data-binary @file.mp4 '<upload_url>'
```

ثم `media_confirm` بنوع `video`.

**انستقرام عبر Composio:**
1. `INSTAGRAM_POST_IG_USER_MEDIA` مع `ig_user_id: me` و`media_type: REELS` و`video_url` والوصف.
2. `INSTAGRAM_POST_IG_USER_MEDIA_PUBLISH` مع `max_wait_seconds: 300`.
3. `INSTAGRAM_GET_IG_MEDIA` لتأكيد الوصف والرابط.

**تيك توك عبر Higgsfield:** `tiktok_accounts`، ثم `tiktok_prepare_publish`. النشر يتم من النموذج بيد المستخدم، ووصف تيك توك بسطر واحد، والنموذج ينتهي بعد قرابة ساعتين. رقم النشر قد لا يوصلك، فإذا ما وصل قل إنك ما تأكدت واطلب منه يشيك الحساب.

**بعد النشر:** اكتب ملخص الرد في `رسالة_<الكلمة>.md`، وحدّث الذاكرة وملف الفيديو، وذكّره بسحب الأرقام بعد 48 ساعة.

## أشياء تعلمناها بالطريقة الصعبة

- لا تكتب ملفات طويلة بـheredoc في Bash هنا: الشرطات المائلة والفواصل تفسدها. استخدم أداة `Write`.
- `Start-Sleep` ممنوع، فاستخدم أمراً في الخلفية بـ`sleep`.
- فحص `Select-String "METR"` يطابق `geometry`، فلا تعتبر عدد المطابقات دليلاً.
- رخصة onetake غير تجارية. هذا الطريق يستخدم محركه الخاص، وأدوات onetake للتحليل والفحص فقط. لو استخدمت مكتبته في الفيلم، نبه المستخدم.
- موسيقى Eleven Music على الخطط الأدنى فيها احتمال قيود حقوق، فذكر به مرة عند اختيارها.
