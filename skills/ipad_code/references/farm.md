# مزرعة الرندر: أجهزة سحابية متوازية

جربناها بعشر جلسات، وكل جلسة ٤ أنوية، على ٨١ إطار ثقيل كانت بتاخذ قرابة ٣ ساعات على جهاز واحد:

- ثمان أجهزة رفعت إطاراتها خلال ١٢ إلى ١٩ دقيقة من فتحها.
- جهاز أخذ ٤٦ دقيقة.
- جهاز وقف قبل ما يرندر، وعالجناه بالطريقة اللي في الخطوة 5.

الوقت الكلي لين اكتملت الإطارات كان قرابة ٥٥ دقيقة، والسبب الجهازين المتأخرين. عشان كذا لا تنتظر الأبطأ وأنت ساكت: ارندر إطاراته هنا من الآخر للأول.

## 1. فرع الوظيفة

الجلسات ما بينها مجلد مشترك، فالمشهد يوصلها عن طريق git. استخدم فرع orphan فيه ثلاث ملفات بس:

```bash
python3 $SK/scripts/farm.py precheck --blend $P/scene.blend   # GitHub يرفض أي ملف فوق 100 ميجا
cd <المستودع>
git worktree add --detach /tmp/job && cd /tmp/job
git checkout --orphan render-job
git rm -rqf .                       # -f ضرورية، بدونها يفشل ويبقى كل المستودع في الفرع
cp $P/scene.blend $SK/scripts/render.py $SK/scripts/setup_blender.sh .
git add -f scene.blend render.py setup_blender.sh   # -f لأن .gitignore ممكن يتجاهل الملفات
git commit -m "Temporary render job (delete after)"
git push -u origin render-job
git ls-tree -l HEAD                 # تأكد إن الثلاث ملفات موجودة وإن scene.blend مو فاضي
```

- ارفع **`scene.blend` نفسه**، مو سكربت البناء. كذا كل الأجهزة ترندر نفس المشهد بالضبط، حتى لو تغير السكربت بعدين.
- لا ترفع على الفرع اللي شغّال عليه المستخدم.

## 2. التوزيع

```bash
python3 $SK/scripts/farm.py plan --frames 1-240 --have $P/frames --workers 10
```

الإطارات الناقصة تتوزع بالتناوب (w01 ياخذ 160 و170 و180 وهكذا). آخر المقطع عادة أثقل بمرتين أو ثلاث، والتناوب يقسم الثقيل على الكل. خلّ هذا الجهاز يرندر حصة صغيرة بعد (أول ٦ إطارات مثلاً)، لأن الأجهزة تحتاج ١٠ دقايق تجهيز.

## 3. فتح الجلسات

لكل جهاز `NN`:

```
create_session(
  title          = "Render worker NN – <اسم المشروع>",
  source_url     = "https://github.com/<owner>/<repo>",
  source_revision= "render-job",
  outcome_branch = "render-out-wNN",      # يعطي الجلسة صلاحية الرفع على هذا الفرع
  tags           = ["<project>-render"],
  prompt         = <ناتج: python3 farm.py prompt --worker NN --list "<إطاراته>" --samples <قيمة الرندر النهائي>>
)
```

- `--samples` إجباري. ملف المشهد ممكن يكون محفوظ بقيمة أعلى (مثال الترانزستور محفوظ بـ 96 والرندر النهائي 28)، وبدونها الأجهزة تبطأ وإطاراتها تختلف عن الرندر المحلي.

- أرسل كل الجلسات في رد واحد (استدعاءات متوازية).
- **لا تحط `permission_mode: plan`**، لأن الجلسة بتنتظر موافقة ما أحد بيعطيها.

## 4. المتابعة

- الجلسة اللي تخلص بنجاح **ما ترجع تبلغك**. جدول `send_later` بعد ٢٥ إلى ٣٠ دقيقة، ورسالته تكون تعليمات كاملة لك (وش تفحص ووش تسوي بعده).
- وقت الفحص:
  ```bash
  git ls-remote origin 'refs/heads/render-out-w*'
  python3 $SK/scripts/farm.py collect --repo <المستودع> --prefix render-out-w --into $P/frames --frames 1-240
  ```
  آخر سطر يطبع `MISSING`.
- لكل جهاز ناقص: `get_session(id)`. حقل `post_turn_summary.status_detail` يقول وين وقف.

## 5. جهاز وقف

صار معنا: جلسة أنهت دورها وهي «تركّب bpy» بدون ما ترندر.

1. `send_message` له: «كمّل الحين: ركّب، ثم ارندر إطاراتك <القائمة> وانتظر لين يخلص الرندر، ثم ارفع. لا توقف قبل الرفع.»
2. وفي نفس الوقت ارندر إطاراته هنا من الآخر للأول (`--frames 233,223,213,...`)، في الخلفية.
3. اللي يخلص أول تاخذ منه، و`collect` ما يكتب فوق إطار موجود.

## 6. التنظيف

- `archive_session` لكل جلسة.
- **الجلسة ما تقدر تحذف فروع من GitHub** (يرجع 403)، فقل للمستخدم: «افتح المستودع في GitHub، ثم Branches، واحذف `render-job` وكل `render-out-w..`.» فيها ملف المشهد وصور الإطارات بس.
- `git worktree remove --force /tmp/job`.

## 7. التكلفة

كل جلسة عاملة استهلكت قرابة ٠٫٥ إلى ١ دولار من التوكنز في تجربتنا، وهذا يُحسب من حد استخدام المستخدم. قله الرقم التقريبي قبل ما تفتح الأجهزة.
